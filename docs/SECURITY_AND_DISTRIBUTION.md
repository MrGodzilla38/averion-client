# Security and distribution

## Trust model

Use HTTPS with platform certificate validation and approved origins throughout. SHA-256 of the exact bytes checks integrity against the signed manifest. A matching checksum from an untrusted publisher can still describe a malicious file. For publisher authenticity, use Sigstore Cosign key-based blob signatures with a pinned public key distributed in trusted Launcher builds. Sign the raw manifest bytes as version 1 and publish the Cosign verification bundle alongside. Verify with a maintained verifier implementing the same Cosign bundle format, using the pinned key and exact unmodified bytes, before trusting URLs or pins. Require a bundled transparency log entry and verify it against trusted Sigstore roots packaged with the Launcher. Validate both the pinned publisher key and the transparency evidence offline for installed generations. Keep the private key under project release custody and rotate the trust root through authenticated launcher updates. GitHub immutable releases and attestations can provide additional provenance and reject asset mutation at the origin. [Cosign blob signing](https://docs.sigstore.dev/cosign/signing/signing_with_blobs/), [Cosign blob verification](https://docs.sigstore.dev/cosign/verifying/verify/), [GitHub immutable releases](https://docs.github.com/en/code-security/concepts/supply-chain-security/immutable-releases).

Cache the highest accepted sequence per channel and Minecraft target. Reject lower sequences for that target in normal updates. Retain the manifest digest per channel and sequence and reject a different digest for a previously seen pair. Per-target tracking permits an older eligible build when a newer release supports a different game version. Ship a minimum accepted sequence per channel in new Launcher builds. Treat replay/freeze as a residual risk for a fresh or long-offline launcher that has no newer trusted checkpoint. Intentional rollback reads the previously authenticated local generation without relaxing future updates. Compromised signing or revocation needs a new trustworthy Launcher release and a revocation floor or blocklist.

## Installation controls

- Bound parsing, fetch size, time, retry count and redirect depth. Parse HTTPS URLs and enforce host/path rules per provider, including approved HTTPS redirect destinations. Check GitHub repository and asset IDs and upstream Modrinth identities. Reject user info, ambiguous URLs and local origins.
- Treat all paths and metadata as untrusted input. Derive destination basenames, enforce containment and refuse symlinks or other redirections in managed paths. Jars install as whole files. If another package requires archive extraction, reject traversal, absolute paths, symlinks, special files and ambiguous duplicates. Limit expanded size and entry count.
- Stage, hash and inspect files before committing under the profile lock. Verify every required dependency. Preserve saves and unmanaged files, and recover interrupted commits using the launcher journal. A hash or signature confirms provenance or integrity, while Fabric mods still execute arbitrary code with the game process's privileges. Restrict initial curated sources and treat user mod choices as a separate trust decision.

## Release and licensing

1. Build and test declared targets from a reviewed source revision using pinned dependencies. Complete target runtime validation before publication. Inspect production jars for expected classes and metadata, exact pins, required notice files and the absence of game code or proprietary assets.
2. Calculate sizes and SHA-256 from production jars. Generate the manifest and validate the dependency closure, channel and sequence. Review release assets before signing. Verify a staged installation from the signed bytes, then publish as an immutable GitHub release. A correction gets a new sequence and a new release. Phase 00 does not automate signing or publishing.
3. Distribute Averion-owned mod artifacts and their required notices. Obtain game files from authorized Mojang services. Keep Minecraft game jars, mappings and proprietary artwork out of distribution. Review Minecraft usage guidelines before branding or publication. Fabric Loader and Fabric API license their source under Apache-2.0, while Loom and Yarn use MIT and CC0-1.0 respectively. Check exact release notices and third-party components separately before redistribution. Gradle's wrapper is upstream build tooling under Apache-2.0.
